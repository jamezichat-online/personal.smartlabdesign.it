# Editor UI Implementation Plan
> For agentic workers: use executing-plans for inline implementation.
**Goal:** Make the existing apartment editor understandable and its panels movable and collapsible.
**Architecture:** Retain original DOM control IDs and callbacks; rearrange groups into six areas, wrap the current sidebar and minimap in window controls and create a contextual inspector. An inline workspace controller owns only UI state in a distinct localStorage key. Keep all code inside the existing HTML.
**Tech Stack:** HTML, CSS, vanilla JS, Three.js, Playwright tests.
**Spec:** docs/superpowers/specs/2026-10-21-editor-ui-design.md
## Global Constraints
- All existing controls, scene behavior, project import/export and IDs survive.
- Six approved areas; left tools, right contextual inspector; progressive disclosure.
- Drag, resize, collapse, local persistence, accessible controls and reset.
- Mobile: one visible working panel; no horizontal overflow; no offscreen header.
- Subtle blur/transparency requested by user takes precedence over skill defaults.
## Review Focus
1. Legacy callbacks that switch tabs must still reveal their target controls.
2. No fields vanish through moving DOM containers or selection refresh.
3. Pointer gestures on controls and canvas must not start panel drags.
4. Small viewports, restored oversized windows and malformed stored layouts remain recoverable.
5. Exported HTML must contain the new interface and preserve project data.
